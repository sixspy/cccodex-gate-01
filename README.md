# 闸口事件湖仓台

码头闸口扫描先落在贴源层，原文照收。建层员选定业务日，按事件字典把扫描收成明细层：进闸、出闸、倒箱。字典里没有的事件码、箱号不合法或时间读不出的扫描留在剔除清单，不进明细。

这里不管堆存量，只处理扫描事件怎么分层。

## 重建口径

贴源落好之后，收成明细之前必须先给业务日定重建口径，写进重建设置。口径只有两种：

| 口径 | 收成方式 |
|------|----------|
| 整层重写 | 整日明细先作废（旧层进废层队列），再全量收成 |
| 只补新扫描 | 只把尚未入库的贴源补进明细 |

规则：

- 口径写进重建设置后，当日不得更换；重建尚未收束时不许改重建设置。
- 构建请求里的口径和重建设置对不上，记「重建口径不符」，这一日不收成。
- 两个建层员同时对同一业务日动手，加锁后只让先到的那次收成，后一次记「重建争用」。
- 贴源条数为零的日子不准进入废层队列。

页面四块同看：日列表（作废层数、补进条数、口径名）、层对照（作废前与收成后的明细）、重建设置、废层队列。
